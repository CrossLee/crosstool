# Windows 主窗口远程可见性修复与验证边界

日期：2026-09-09。本记录描述本次 Windows 候选修复，不代表已发布版本、已安装版本或用户真机结果。

## 问题与修复边界

此前主窗口错误使用了 `WDA_EXCLUDEFROMCAPTURE (0x11)`。这会让本机仍有任务栏图标和窗口进程，但依赖桌面捕获的远程控制软件可能拿不到主窗口画面。普通一爪主窗口现在固定按 `WDA_NONE (0)` 验收，不再使用排除捕获属性；因此主窗口应能进入桌面合成和远程画面。

排除捕获并未从所有窗口移除。下面两类辅助 UI 仍保留 `WDA_EXCLUDEFROMCAPTURE`，避免它们污染用户要保存的图片：

- “贴到屏幕”生成的截图固定窗；
- 长截图的选区边框和操作工具栏。

这个区分是有意的：普通主窗口必须可被远程桌面看见，截图固定窗与长截图辅助 UI 则继续不进入截图或录屏内容。

## 捕获前隐藏和重开规则

开始截图、取色或录屏前，主窗口先调用隐藏，再等待桌面合成确认。当前实现使用 `DwmFlush`，失败或状态尚未收敛时按约一帧的间隔做有界重试；取色在该屏障之后还保留采样等待。这样避免只改变窗口状态但旧帧仍被截进结果。

隐藏期间不能由开始菜单、第二次 AUMID 激活、普通启动或通知区域“打开”把主窗口重新带回画面：

- 截图、取色等视觉操作持有统一的 feature gate 时，主窗口重开请求被拒绝；
- 录屏处于能力检查、启动、录制或停止封装阶段时，主窗口重开请求被拒绝；
- 操作结束后再次启动或从通知区域打开，已最小化的窗口会恢复，越出当前显示器工作区的窗口会重新放回可见区域，再显示并激活。

录屏时主窗口保持隐藏，但停止能力不能随主窗口一起消失。候选设计保留三条无需重开主窗口的控制路径：

- 通知区域图标的右键菜单在录制中提供“停止并保存录屏”；
- 处于 `CheckingCapabilities` 或 `Starting` 时，同一控制入口执行取消，避免启动过程卡住后只能结束进程；
- 已进入录制后，再按同一录屏快捷键仍执行停止并保存。

这些入口只改变录屏状态，不以显示主窗口为前提。自动测试可以验证状态到菜单命令、取消或停止动作的映射，以及主窗口显示门禁；它不能替代真机上右键菜单是否实际可达、物理快捷键是否触发、MP4 是否完成封装的人工验收。

## 自动验证覆盖

Windows 启动与安装验收不再只看 PID、窗口标题和 `IsWindowVisible`。候选脚本要求主窗口同时满足：

- 属于本次测试进程，标题为“一爪”，连续两次检查保持有效；
- `IsWindowVisible=true`、非最小化、`DWMWA_CLOAKED=0`；
- `GetWindowDisplayAffinity` 成功且值严格为 `WDA_NONE (0)`；
- `GetWindowRect` 宽高为正，并与至少一个活动显示器的工作区相交；
- UI Automation 根窗口可用、启用、未离屏，`WindowPattern` 不是最小化状态；
- UI Automation 能找到可见、启用且有正尺寸的“首页”关键元素，并确认其具有文本或可交互语义。

MSIX 安装验收还会在首次启动通过后隐藏该精确主窗口，在原进程仍存活时再次通过同一 AUMID 激活，并要求原主进程恢复出满足上述条件的主窗口。测试只终止自己持有的测试进程，并只清理隔离安装的测试包。

本机已通过 Windows 工作流与窗口验收脚本的静态合同测试 `19/19`，并通过 YAML 解析和 `git diff --check`。本机没有 Windows PowerShell、Windows UI Automation、WinUI 或 DWM 环境，因此这些结果只证明脚本合同和配置结构，不等于 Windows 动态验收。新的 Windows CI 动态结果必须以包含本修复的对应 Actions 记录为准；本文不把未列出的运行视为已通过。

## 尚未证明

以下项目仍须在与用户场景一致的设备上单独验收，不能由托管 CI 或 API 状态替代：

- Windows 11 x64 实体机从 Setup.exe 安装后，启动、最小化、移出屏幕、多屏切换及驻留进程再次激活；
- UU Remote 实际连接时，远端画面能逐像素看到主窗口内容，而不是只有任务栏图标；
- 截图、取色和录屏结果逐像素不包含主窗口旧帧，同时截图固定窗、长截图边框及工具栏确实不进入成片；
- 主窗口保持隐藏时，通知区域右键“停止并保存录屏”、`CheckingCapabilities` / `Starting` 取消和同一录屏快捷键停止在真实输入下均可达，且最终 MP4 可播放；
- 不同显卡、DPI、混合缩放、多显示器和远程会话重连下的合成时序。

Windows 11 ARM64 托管 runner 即使通过，也只能证明对应 runner 的安装、窗口状态和 UI Automation 合同；它不是 UU Remote，也不能代替 Windows 11 x64 用户真机的像素级画面证据。
